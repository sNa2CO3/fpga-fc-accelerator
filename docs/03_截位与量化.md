# 03 截位与量化

[← 返回总览](00_项目总览.md)

> 本篇是 Lab6 的核心内容，也是整个项目"为什么用 8bit"的论据。
> 答辩时最容易被追问的三件事都在这里：**移位量怎么定、为什么逐层重算、8bit 为什么够**。

---

## 1. 为什么要截位

Lab5 的三层网络是"位宽逐层加宽"的：

| 层 | 输出最大值 | 二补码位宽 | 该层乘法器 |
|---|---|---|---|
| fc1 | 80 805 | 17 | 8×8 |
| fc2 | 39 386 422 | 26 | 32×8 |
| fc3 | 17 379 948 761 | 35 | 48×8 |

三层位宽不同 → 三套乘法器阵列 → **DSP 152 个**（64×1 + 32×2 + 8×3），
布线长、功耗高、三层还不能共用资源。

如果把每层输出都截成 8bit，三层立刻变成"同一件事"——都是 8×8 乘法，
于是**一套 64 路阵列就能分时复用**，DSP 降到 64（−57.9 %）。
这是 Lab6 在硬件上的直接收益，也是 Lab8 能用一片 7020 跑起来的前提。

## 2. 截位的数学形式

```verilog
y_trunc = (y >>> SH)[CUT_W-1 : 0]        // 再符号扩展到 8bit 存储
```

- 正数：`>>>` = 除以 `2^SH` 向下取整；
- 负数：`>>>` 是**向负无穷取整**（算术右移），与"取二补码高位段"完全一致。
- **必须用 `$signed` 算术右移**：fc3 输出可以为负，用逻辑右移 `>>` 会补 0，结果直接错。

RTL 里是纯组合的位选择，**不加流水级**，所以加不加截位 `DLY_OUT` 都是 15。

## 3. 移位量怎么定

设某层输出最大绝对值为 `M`，有符号二补码位宽 `B = bit_length(M) + 1`，
要装进 `CUT_W` 位：

```
SH = bit_length(M) - (CUT_W - 1)
```

即课件第 12 页的"`1(符号位) + 有效位宽 − 存储位宽`"。

### 3.1 为什么必须逐层重算

课件第 11 页第 2 条："同时考虑前一层输出截位后对后面一层结果的影响"。
**这不是可选项**：截位改变下一层的输入，进而改变下一层的值域。

第 2 层的 39 386 422 是"第 1 层不截位"时的统计值。
第 1 层右移 10 位后，第 2 层的实际最大值只有 **37 683**——差三个数量级。
用原始值定移位量会严重过移，把结果压成 0。

所以必须串行推导：

```
SH1 ← M1（原始第 1 层最大值）
T1  ← (第 1 层输出) >> SH1
M2' ← 用 T1 实算出的第 2 层最大值      ← 注意是 M2'，不是 M2
SH2 ← M2'
...
```

### 3.2 最终参数

| 方案 | 层 | 该层实算最大值 | 位宽 | **SH** | 截位后范围 |
|---|---|---|---|---|---|
| **8bit** | fc1 | 80 805 | 17 | **10** | [0, 78] |
| | fc2 | 37 683 | 16 | **9** | [0, 73] |
| | fc3 | 32 166 | 15 | **8** | [-126, 76] |
| **4bit** | fc1 | 80 805 | 17 | **14** | [0, 4] |
| | fc2 | 1 716 | 11 | **8** | [0, 6] |
| | fc3 | 2 588 | 12 | **9** | [-6, 3] |

检查：8bit 的 fc3 范围 `[-126, 76]` 落在 `[-128, 127]` 内；4bit 的 `[-6, 3]` 落在 `[-8, 7]` 内。
说明移位量既没取小（不会溢出）也没取大（不浪费码值）。

### 3.3 与课件例题的核对

课件第 12 页 8bit 例题：

- 第 1 层：`80805`，`2^16 < 80805 < 2^17` → `1+17-8 = 10`，取 `[17:10]`。✅ 与本文一致。
- 第 2 层（**更正版**）：`39386422/2^10 ≈ 38464`，`2^15 < 38464 < 2^16` → `1+16-8 = 9`，取 `[16:9]`。✅ 与本文一致。

> 旧版课件写的是 8。检查一下就知 8 不够：第 2 层实测最大值 37 683，右移 8 位得 147，
> 超过 8bit 有符号上限 127，会溢出成负数。更正版的 9 正好把最大值压到 73。

## 4. 截位方案的对比结果（42 个样本）

| 方案 | 平局数 | 准确率（平局判 1） | 准确率（平局判 0） |
|---|---|---|---|
| 未截位（Lab5） | 0 | **37/42 = 88.10 %** | 37/42 = 88.10 % |
| **8bit 截位** | 0 | **37/42 = 88.10 %** | 37/42 = 88.10 % |
| 4bit 截位 | **27** | 21/42 = 50.00 % | 36/42 = 85.71 % |

**结论：8bit 截位不损失任何分类能力**——42 个样本的预测与未截位**逐一相同**。

### 4.1 样本 1 的逐层对比

| 层 | 未截位 | 8bit（存值） | 4bit（存值） |
|---|---|---|---|
| fc1 通道 0~7 | 4888, 1251, 0, 0, … | **4, 1**, 0, 0, … | **0, 0**, 0, 0, … |
| fc2 通道 0~7 | 2 194 586, 0, 2 197 742, … | **3, 0, 3, 0, 0, 2, 5, 0** | **0, 0, 0, 0, 0, 0, 0, 0** |
| fc3 `(y1, y2)` | (1 444 462 170, −1 667 237 270) | **(10, −11)** | **(0, 0)** |
| 判定 | y1 > y2 → 标签 0 | 10 > −11 → 标签 0 | 平局 |

- **8bit** 把 fc3 压到 `10` 和 `−11`，**符号关系完全保留**，判定不变；
- **4bit** 把两者都压成 `0`，**判别信息彻底丢失**。

### 4.2 为什么 4bit 会塌缩

4bit 只有 16 个码值（−8~7），而 fc3 的合法范围本身就是 `[-6, 3]`——有效码值只剩 10 个。
结果 42 个样本里 **27 个落到 `y1 == y2`**，网络从"分类器"退化成"几乎不做区分"。

此时准确率**不反映网络能力**，完全由平局判据决定：判 1 得 50 %，判 0 得 85.7 %。

> 一个有意思的旁证：4bit 下 **15 个非平局样本全部判对**。
> 说明截位没有"把网络搞坏"，而是**把输出分辨率压到了判据无法分辨的程度**。

## 5. Lab8 的输入输出约定

课件第 5 页要求：

> 输入输出均为 8bit 有符号数（−128~127）；
> 输出数据最大值应大于 63 小于 127，或最小值大于 −128 小于 −64（保证截位结果正常）。

对照我们的实测值：

| 要求 | 本设计 | 是否满足 |
|---|---|---|
| 输入 8bit 有符号 | 输入字节就是 `signed char` | ✅ |
| 输出 8bit 有符号 | fc3 存值 | ✅ |
| 最大值 ∈ (63, 127) | **76** | ✅ |
| 最小值 ∈ (−128, −64) | **−126** | ✅ |

也就是说，8bit 的移位量 10/9/8 恰好让输出"用满但不溢出"——这是刻意调的，
不是碰巧。如果移位量取大了（例如 fc3 取 9），最大值会掉到 38，不满足课件要求。

## 6. 如果要在 Lab8 里再调量化

课件的评分里准确率占 25 %，而且明确提示"调整截位方式、对原始模型重新量化"。
可做的方向（按代价从低到高）：

| 方案 | 做法 | 预期 | 代价 |
|---|---|---|---|
| ① 微调移位量 | fc3 用 SH=8 已是最优（范围 −126~76）。改成 7 会溢出 | 无提升 | 无 |
| ② 4bit 换平局规则 | 平局时用原始输入的符号或能量兜底 | 4bit 从 50 % → 85.7 % | 要改判据，且 8bit 本来就没平局 |
| ③ 重新量化权重 | 用 `2-FCNet1-485-0.945.pth` 做 QAT，让 8bit 权重更贴合 | 可能 +2~5 % | 需要 PyTorch 训练环境 |
| ④ 混合位宽 | fc1 用 8bit、fc2/fc3 用更高位宽 | 准确率接近 100 % | DSP 回升，面积/功耗变差 |

> 注意：本设计的 88.10 % **不是量化损失**，而是**原始 INT8 模型本身的准确率**——
> 未截位网络也是 37/42。所以想提高准确率必须动模型（方案 ③④），而不是动截位。

### 2.0.2 时间口径（汇报必看）

| 口径 | 数值 | 用途 |
|---|---|---|
| **NPU 三层计算** | **9.152 µs**（1144 拍 @125 MHz） | 纯计算；和参考榜 7.585 µs 对比用这个 |
| 单张整包（含收发） | **10.712 µs**（1339 拍） | 再加命令 1 + 收样本 192 + 输出 2 |
| 逐张上板（B=1） | **75.85 µs/张** = MM2S 约 48 + S2MM 约 28 | 说明每笔 DMA 的固定开销 |
| **整批上板（B=42）** | **11.6 µs/张**（488 µs / 42 张） | **交付口径**，见 05 篇 §6 |
| 端到端（Python） | 脚本 `[t]` 分段打印 | 说明启动开销在软件侧 |

> **为什么逐张时 NPU 只占 75.85 µs 里的 1/7**：
> - MM2S 搬 520 字节用了约 48 µs ≈ **10.8 MB/s**。单次只有 520 字节，DMA 的启动/寻址
>   延迟占主导，不是带宽不足——实测 8 字节与 520 字节耗时几乎相同；
> - S2MM 的约 28 µs 也不随频率变化，说明它被异步 FIFO 跨域与 DMA 完成检测的固定开销占住了。

**批处理已完成并上板验证**：把 42 张合并成一次 DMA，固定开销摊到 1/42，
硬件时间从 75.85 降到 **11.6 µs/张**；B=1/2/4/8/21/42 六种批大小的分类结果逐样本相同，
脚本默认 `BATCH = 42`（可用 `LAB8_BATCH` 环境变量覆盖）。
实现细节与实测见 05 篇 §6、08 篇 §3。

### 2.1 一键脚本（推荐）

```bash
cd D:/VivadoProject/Lab8
vivado.bat -mode batch -source scripts/setup_project.tcl
vivado.bat -mode batch -source scripts/create_ip.tcl
vivado.bat -mode batch -source scripts/build_bd.tcl
```

`build_bd.tcl` 会建出：

```
processing_system7_0 ──┬── M_AXI_GP0 ──► ps7_0_axi_periph ──► axi_dma_0/S_AXI_LITE
                       ├── S_AXI_HP0 ◄── axi_mem_intercon ◄── DMA M_AXI_MM2S / S2MM
                       └── FCLK_CLK0 (100 MHz) 给所有模块

axi_dma_0/M_AXIS_MM2S ──► pl_fc_top_0/s_axis_*
pl_fc_top_0/m_axis_*  ──► axi_dma_0/S_AXIS_S2MM
```

> ⚠️ 脚本跑完**一定要在 GUI 里打开 `design_1` 检查连线**（脚本不能保证 100 % 正确），
> 确认无误后再右键 → *Generate Output Products* → *Create HDL Wrapper*。

### 2.2 GUI 手动步骤（如果脚本有问题）

1. **Create Block Design**，命名 `design_1`；
2. 添加 **ZYNQ7 Processing System** → *Run Block Automation*（应用 board preset）；
3. 双击 PS7 → *PS-PL Configuration*：
   - 勾选 `M AXI GP0 interface`、`S AXI HP0 interface`；
   - *Clock Configuration* → `FCLK_CLK0 = 125 MHz`（最终版；100 MHz 也能跑，见 05 篇 F8）；
4. 添加 **AXI Direct Memory Access**，双击配置：
   - 取消 `Enable Scatter Gather Engine`（简单模式）；
   - `Width of Buffer Length Register = 26`；
   - *Read Channel* / *Write Channel* 都保留，Stream Data Width 设 **64**；
   - 关闭 `Allow Unaligned Transfers`；
5. 添加 **Processor System Reset**；
6. 把 `pl_fc_top` 加进来：*Add Module* → 选 `pl_fc_top`（工程里已有源码）；
7. 连线（参考上面的图）：
   - `FCLK_CLK0` → DMA 的 `s_axi_lite_aclk` / `m_axi_mm2s_aclk` / `m_axi_s2mm_aclk`、interconnect 的 `aclk`、`pl_fc_top` 的 `s_axis_aclk` 和 `fc_clk`；
   - `peripheral_aresetn` → `pl_fc_top/rst_n`、DMA 的 `axi_resetn`；
   - AXIS：`M_AXIS_MM2S_*` ↔ `s_axis_*`，`m_axis_*` ↔ `S_AXIS_S2MM_*`；
8. **Run Connection Automation**（会自动加 interconnect / 地址分配）；
9. *Validate Design* → 无错误；
10. *Generate Output Products* → *Create HDL Wrapper*（选 *Let Vivado manage*）；
11. 右键 wrapper → *Set as Top*；
12. **Generate Bitstream**（约 10–20 分钟）。

### 2.3 导出上板文件

`File → Export → Export Hardware`（勾选 *Include bitstream*），
得到 `design_1_wrapper.xsa`（旧版是 `.hwh` + `.bit`）。

把这两个文件改名成 PYNQ 认的格式：

```
design_1_wrapper.bit   →  lab8.bit
design_1_wrapper.hwh   →  lab8.hwh     (PYNQ 2.7 仍用 .hwh)
```

> 然后在 `Lab8.gen/sources_1/bd/design_1/hw_handoff/` 下能找到 `.hwh`。

## 3. 板子侧

### 3.1 拷贝文件

把下面 4 个文件放到 PYNQ 的同一个目录（例如 `/home/xilinx/lab8/`）：

```
lab8.bit
lab8.hwh
sel_data.coe          ← 老师提供，42 × 512 字节
sel_labels.txt        ← 老师提供，42 个标签
lab8_npu.py           ← 本项目 sw/ 目录下
```

### 3.2 运行

```bash
cd /boot            # 或你上传到的目录
python3 lab8_npu.py
```

> **不要加 `sudo`**。PYNQ 镜像已经用 udev 规则把 FPGA manager 和 `/dev/mem`
> 的权限给了 `xilinx` 用户，而 `pynq` 库装在 `xilinx` 的 Python 路径下 ——
> `sudo` 会切换到 root 的 `sys.path`，直接报 `No module named 'pynq'`。
> 若确有权限问题，用 `sudo -E python3`（保留环境变量），而不是裸 `sudo`。

### 3.3 期望输出

```
=== Lab8 NPU on PYNQ-Z2 ===
command 0x01 = inference, 0x02 = feature map
  sample  1 : result = 0  label = 0  (   xx.xx us)
  sample  2 : result = 0  label = 0  (   xx.xx us)
  ...
  sample 42 : result = 0  label = 1  (   xx.xx us)

  accuracy      = 37/42 = 88.10 %
  total time    = xxxx.xx us
  average time  =   xx.xxx us/sample

  sample 1 feature map (162 bytes):
    fc1[0:8] = [4, 1, 0, 0, 0, 0, 0, 0]
    fc2[0:8] = [3, 0, 3, 0, 0, 2, 5, 0]
    fc3      = [10, -11]
```

**这三行特征图必须和这里一模一样**——它们是 Lab7 仿真验证过的值，
可以作为上板是否正确的第一道判据。

> **时间怎么报**（三个口径，说清楚就不会被追问）：
> - **PL 三层计算**：1144 拍，125 MHz 下 9.152 µs；整包含收发为 1339 拍、10.712 µs；
> - **端到端 PS→PL→PS**：脚本一次 DMA 送 42 张，**11.6 µs/张**（`batch HW time`）；
> - **脚本总耗时**：约 2 s，其中 1.7 s 加载比特流、0.18 s 读样本，推理只占 0.5 ms。
>
> 不要用 `time python3 lab8_npu.py` 的 12 s 当性能数字——那里面约 10 s 是 `import pynq`。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Overlay` 报 "no such IP" | .hwh 和 .bit 不匹配 | 确认两者同一次 Generate Bitstream 产出 |
| 42 个结果全是 0 或全乱 | 字节序反了 | 检查 PS 打包是否 **MSB 优先**（见 01 篇 §4.1） |
| 只跑第一个样本就卡住 | DMA S2MM 收不满（tlast 没发对） | 检查 `output_data_last`、`m_axis_tlast` |
| 特征图只有前 8 个字节对 | 打包级 cnt 没清零 | 检查 `fc_out_packer` 的 `flush` 分支 |
| `dma.recvchannel.wait()` 超时 | S2MM 长度配小了 | 特征图要 168 字节（21×8），推理 8 字节 |
| 板子跑起来但没结果 | `peripheral_aresetn` 没接 | BD 里检查 `rst_ps7_0_100M/peripheral_aresetn` |

## 5. 演示脚本（现场 5 分钟）

1. **开场（30 s）**：打开 Vivado 的 Block Design，一句话说清
   "PS 用 DMA 把 512 字节样本送进 PL，PL 里的 NPU 算完把结果送回来"。
2. **跑 42 个样本（2 min）**：SSH 到板子执行 `python3 lab8_npu.py`，
   现场看准确率 88.10 % 和时间。
3. **特征图（1 min）**：脚本末尾会打印样本 1 的三层特征图，和仿真值对照。
4. **资源与功耗（1 min）**：打开 Vivado 的 `report_utilization` 和 `report_power`。
5. **优化讨论（1 min）**：讲 05 篇的三条路线，重点说清"为什么选 64 车道不用 128"。

## 6. 如果时间紧：最小可交付路径

1. 先用 `scripts/build_bd.tcl` 建 BD，GUI 检查；
2. 只跑 **样本 1 的推理**（改脚本里 `N_SAMPLES` 为 1），确认通路通；
3. 再跑 42 个；
4. 最后跑特征图模式。

分三步走，任何一步出问题都容易定位。

## 一、一句话概括

在一块 PYNQ-Z2（Zynq-7020）上，从零搭出一台**能跑完整三层全连接网络（512→128→32→2）的神经网络加速器**：
PL 端是自研的 NPU（64 路乘法阵列 + 加法树 + 三层流水 + 指令状态机），
PS 端用 DMA 通过 AXI-Stream 送 512 字节样本、收回分类结果，42 张图 **88.10 %** 准确率，
端到端 **11.6 µs/张**（42 张一次 DMA；逐张模式为 75.85 µs/张）。

## 二、演进路线：五个实验怎么长成一台加速器

| 实验 | 主题 | 在最终系统里的位置 | 关键产出 |
|---|---|---|---|
| Lab3 | 同步 / 异步 FIFO | AXI 时钟域 ↔ NPU 时钟域的跨时钟域缓冲 | `syn_fifo` / `asy_fifo` |
| Lab4 | 1 层网络计算模块 | NPU 的第一层（512→128） | 64 路乘法阵列 + 加法树 + 延迟链 |
| Lab5 | 3 层网络计算模块 | NPU 的完整数据通路 | `fc1/fc2/fc3` + 层间 RAM + 打包级 |
| Lab6 | 数据截位方式对结果的影响 | NPU 的**数值格式**（8bit 有符号）与**阵列共用** | 截位方案 10/9/8、DSP 152→64 |
| Lab7 | 网络数据流控制 | NPU 的**控制层**（指令、状态机、特征图回读） | 9 状态机 + 两种工作模式 |
| Lab8 | 系统整合（本次） | **整机**：NPU + AXIS 封装 + DMA + PS | 上板可跑的完整系统 |

一句话记住这条线：**Lab4 造零件 → Lab5 造通路 → Lab6 定数值格式 → Lab7 加控制 → Lab8 接上主机。**

Lab1 / Lab2 是个人实验（PS-PL 交互 / Verilog 基础），不在这条线上，但 Lab1 的
`axis_rd_interface.v` / `axis_wr_interface.v` 是 Lab8 的起点。

## 三、最终系统长什么样

```
┌──────────────────────────── Zynq-7020 ────────────────────────────┐
│  PS (ARM Cortex-A9)                                               │
│    └─ DDR 里放 42 个样本、标签、结果缓冲                            │
│         │ AXI4 (HP0)                                              │
│  ┌──────┴──────────── PL ────────────────────────────────────────┐ │
│  │  AXI DMA (MM2S/S2MM, 64bit, 简单模式)                          │ │
│  │     │ M_AXIS_MM2S                    S_AXIS_S2MM │            │ │
│  │     ▼                                            ▲            │ │
│  │  axis_rd_interface ──► fc_top ──► packer ──► axis_wr_interface │ │
│  │   (异步 FIFO CDC)       (NPU)     (8b→64b)     (异步 FIFO CDC) │ │
│  │                          │                                     │ │
│  │         ┌────────────────┴─────────────────┐                   │ │
│  │         │ FC1 → FC2 → FC3（三层全连接）      │                   │ │
│  │         │ 共用 64 路 8×8 乘法阵列 + 加法树   │                   │ │
│  │         └──────────────────────────────────┘                   │ │
│  └────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

两个工作模式：

| 模式 | 指令 | PS 发什么 | PL 回什么 |
|---|---|---|---|
| 推理 | `0x01` | 指令字 + 64 个字（512 字节样本） | 1 字节分类结果（0/1） |
| 特征图 | `0x02` | 只有指令字 | 162 字节（fc1 128 + fc2 32 + fc3 2） |

## 四、核心指标

| 指标 | 数值 | 说明 |
|---|---|---|
| 分类准确率 | **37/42 = 88.10 %** | 与未截位软件模型逐样本一致 |
| **端到端 PS→PL→PS** | **11.6 µs/张**（一次 DMA 送 42 张） | 逐张模式为 75.85 µs/张，见 05 篇 §6 |
| PL 三层计算 | **1144 拍 = 9.152 µs** @125 MHz | 纯计算，PPT 用这个口径 |
| PL 整包（含收发） | 1339 拍 = 10.712 µs @125 MHz | 再加命令 1 + 收样本 192 + 输出 2 |
| DSP48E1 | **64 / 220（29.09 %）** | 三层共用一套阵列 |
| Block RAM | 63 / 140（45.00 %） | 主要是"宽度"吃掉的 |
| LUT / FF | 12 430 / 16 331 | 整机（含 BD 的 DMA / 互联 / PS7 包装） |
| 时序 | **WNS +0.403 ns @8 ns**，0 失败端点 / 63 279 | 关键路径：状态机 → DSP B 口，4 级逻辑 |
| 功耗 | **1.653 W**（动态 1.506 + 静态 0.147） | 整机 `report_power` |
| 数值格式 | 8bit 有符号（-128~127） | 三层全部截位 |

## 五、这个项目真正的难点（答辩时的核心论据）

1. **流水线延迟链的对齐**。一个数从地址发出到加法树输出要走 12 拍（`L_RAM 3 + L_MULT 3 + D_TREE 6`），
   累加、加偏置、ReLU、截位分别落在第 12/13/15 拍。**只要有一个常数错 1 拍，结果就全错但不会报错。**
   我们用"第一层先跑通再往下做"的办法把这个常数锚死了。
2. **位宽与截位的取舍**。Lab5 里三层位宽 8→32→48→64，DSP 要 152 个；
   Lab6 用逐层截位把三层都压到 8bit，于是**一套 64 路阵列就能三层分时复用**，DSP 降到 64。
3. **控制状态机与数据通路的配合**。Lab7 的 9 状态机要在"推理"和"特征图回读"两条支路间切换，
   而层间 RAM 在两个支路里地址/写使能的含义完全不同——靠"三种状态互斥"来复用同一块 RAM。
4. **跨时钟域**。Lab8 里 AXI 域和 NPU 域可能不同频，所有数据都要过异步 FIFO（格雷码指针）。
